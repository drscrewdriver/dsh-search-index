# dsh-search-index

> **Поисковый индекс** для боковой панели веб-интерфейса DSH: добавляет в нижней части боковой панели пункт **«Поиск»**, плавающая панель которого одним кликом переключается между **поиском по заголовкам ↔ поиском по содержимому**; режим содержимого показывает заголовки и найденные фрагменты **сгруппированными по сессиям**, с фильтрацией по категориям **пользователь / ответ / инструмент**. Несёт с собой **собственный индекс** (независимый от официального полнотекстового индекса DSH) с инкрементальной синхронизацией, неразрушающей пересборкой и экспортом/импортом снапшотов.

> **Этот пакет занимается только поиском и индексом.** Просмотр и очистка истории сессий (бывшая панель «архивные сессии») переехали во вкладку «Архивная комната» **`dsh-session-steward`**; этот пакет по-прежнему **читает** официальный архивный набор, чтобы исключать архивированные сессии из индекса, но больше **не пишет** в него — у архивного набора только один писатель: стюард. Контракт описан в `dsh-归档文件格式契约-20260914.md`.

Без правок исходников dsh и без PR: cordis-клиент плюс хост-половина плагина, собранные командой `dsh plugin` и патчем бандла.

## Предшественник и текущая версия

**Предшественник: `dsh-session-search-toggle`.** Та версия полагалась на `defineStore` из `@deepseek-ai/dsh-client-runtime`, чтобы получить место для строки настроек. DSH 0.1.2 переименовал/перестроил клиентские engine-пакеты (`dsh-client-runtime` → `dsh-client-store`), и старый код больше не загружался на новом хосте — один плагин не мог покрыть обе версии одним артефактом.

**Текущая версия (`dsh-search-index` 0.6.0) делает основной линией DSH 0.2.0** (peer `>=0.2.0-rc.1 <0.2.1-0`). Исторические хостовые линии обслуживаются отдельными версионными линиями: DSH 0.1.7 обслуживается версией 0.5.7 (npm dist-tag `dsh-0.1.7`, ветка `compat/0.1.7`); более старые хосты 0.1.1/0.1.2 используют устаревший артефакт, который дальше этой версии не развивается. Историческая подоплёка:

- **Один артефакт, адаптивный в рантайме**: тот же `lib/client.js` загружается и на 0.1.1-rc.2, и на 0.1.2-rc.1, **без единой ветки по строкам версии**. Клиентский бандл делает `require` только `react` / `react-dom`, а оба лежат в общей таблице модулей обеих версий.
- **Ни один из engine-пакетов не импортируется**: ни `dsh-client-runtime`, ни `dsh-client-store` — так что переименование ему **не страшно**.
- **Место store реализовано локально**: строке настроек нужно место store (`StoreHandle` / `StoreInstance`, контракт принадлежит `@deepseek-ai/dsh-client-ui-slots` и совпадает в обеих версиях). Плагин заменяет `defineStore` локальной реализацией строк на тридцать — она зависит только от `create()` → `{ actions, getSnapshot, subscribe, clearPersisted }`, без единого specifier'а, привязанного к версии.
- **Все остальные контракты совпадают в обеих версиях**: слот `settings.general.item`, `SettingsScope.{getSnapshot,subscribe,set,unset}` и три поверхности запросов `sessionQuery` имеют одинаковые сигнатуры.

> | 0.1.7-rc.1+ | ✅ | 0.5.7 (dist-tag `dsh-0.1.7`); configForms получает хендл по entry id, старые хосты откатываются на settingsScope, привязанный по пространству имён |
> | 0.1.1-rc.2 | ✅ (устаревший артефакт, заморожен) | store-движок находится в `@deepseek-ai/dsh-client-runtime/client` |

**Обновление со старого имени**: этот пакет — переименование `dsh-session-search-toggle`; id регистрации клиента, id cordis-патча и адрес репозитория переименованы вместе с ним. GitHub сохраняет редиректы для переименованных репозиториев, поэтому старое имя по-прежнему резолвится — но переведите profile-зависимость на новое имя, а не оставляйте два имени сосуществовать надолго:

```sh
dsh plugin --profile web add github:drscrewdriver/dsh-search-index#master
dsh plugin --profile web remove dsh-session-search-toggle
dsh web   # перезапуск
```

Пространство имён настроек остаётся `switch-search` (**ключ хранения стабилен, миграция не требуется**), так что старая конфигурация продолжает работать под новым пакетом.

## Что он умеет

- **Двойной режим заголовок ↔ содержимое**: один вход, два способа искать — «Заголовок» фильтрует в реальном времени по подстроке названия сессии / рабочего каталога; «Содержимое» ищет по телам сообщений через **собственный индекс этого плагина**.
- **Содержимое, сгруппированное по сессиям**: каждый результат поиска по содержимому — одна строка на сессию (название сессии + сильнейший фрагмент + метка типа); клик открывает сессию, без заваливания экрана сообщениями по одному.
- **Фильтр по типу содержимого**: чипы фильтров вверху режима содержимого — **Все / Пользователь / Ответ / Инструмент**; `Инструмент` впускает в результаты события `tool/call` и `tool/result` — можно искать прямо по аргументам и возвращаемым значениям вызовов инструментов.
- **Сортировка результатов**: **Релевантность / Время** справа на той же строке — «Время» сортирует по **времени последней активности сессии**, недавно тронутые — впереди; настройка запоминается локально и переживает перезагрузки. Каждый результат передаёт и время документа, и время сессии — фронтенд может пересортировать сам.
- **Заголовки в реальном времени**: хост подписан на `session/event`, переименование (`session/title`) сразу схлопывается в индекс, не дожидаясь следующего цикла синхронизации (по умолчанию 30 с).
- **Карточка настроек**: Настройки → Плагины обзаводятся карточкой **«Поисковый индекс»** — переключатель включения, режим поиска по умолчанию, настройки синхронизации / числа хранимых копий / каталога собственного индекса и блок жизненного цикла индекса (статус, неразрушающая пересборка, экспорт/импорт снапшотов). Когда карточка сообщает «Исключено N архивированных сессий», она **тут же указывает, кто отвечает**: просмотр и очистка архивированных сессий — забота **«стюарда сессий»** (`dsh-session-steward`), а этот плагин только читает архивный набор; если тот не установлен, подсказка прямо об этом говорит («сейчас не установлен») — вывод делает хост, резолвя пакет по **графу модулей самого плагина**, а при неопределённом результате действует нейтральный текст: **«не читается» никогда не выдаётся за «не установлен»**.
- **Клавиша вызова и платформенные подсказки клавиш**: и вход боковой панели, и полоса клавиш внизу панели показывают клавишу вызова — `⌘K` на macOS, `Ctrl K` на Windows/Linux, по работающей системе; клавиша закрытия панели тоже платформенная (`esc` на macOS, `Esc` в остальных случаях). Определение каскадно падает **UA-CH → `navigator.platform` → строка UA**, и режим приватности никогда не понижает пользователя Mac до Windows-символов. **Подсказка и биндинг из одного источника**: аккорд на капсуле — ровно тот, что распознаёт обработчик `keydown`; никакого «на капсуле одна клавиша, срабатывает другая».
- **Переход по клику**: клик по результату открывает соответствующую сессию и позиционирует на контекст, где найдено совпадение.

## Собственный индекс: три механизма

Режим содержимого **строит свою базу**, не полагаясь на официальный полнотекстовый индекс DSH `session-query-sqlite`. Индекс живёт в `src/host/`: `schema.ts` создаёт таблицы (включая собственную FTS5-таблицу `docs_fts`), `engine.ts` ведёт запросы, `extract.ts` извлекает из событий сессии искомый текст (включая имя и аргументы инструмента у `tool/call` и текст результата у `tool/result` — та самая база данных для «фильтра по инструментам»). `sessionQuery` DSH используется только как **читатель корпуса** (`listSessions` / `readSession`), не как поисковый бэкенд.

### 1. Независимый индекс содержимого сессий

Индекс — **собственный SQLite-файл этого плагина**, официальный индекс он никак не затрагивает. Каталог хранения настраивается, доступны экспорт/импорт снапшотов и полная пересборка. При активации хост инспектирует каталог индекса: недостроенный `index.building.sqlite` при живом активном индексе трактуется как «прошлая пересборка не завершилась» и просто выбрасывается; если активного нет — «краш попал в окно переименования», и новейший архив откатывается в активные.

### 2. Вышедшие из употребления сессии вычищаются по архиву, обновление идёт по кругу

`archive-source.ts` читает `global.archivedSessionIds` из официального хаба хранения `~/.dsh/storages/workspace.json` и держит **архивированные (то есть уже непригодные) сессии вне индекса**. У архивного набора один писатель — стюард; этот пакет только читает и не пишет.

Синхронизация **скользящая**: `SwitchWatermarkSync` в `sync.ts` ведёт водяной знак `version` для каждой сессии и за проход сравнивает только различия и перезаливает только изменившиеся сессии — никакой полной пересборки. Сами файлы индекса хранятся в ограниченном числе копий по `archiveKeep`, старые автоматически уходят.

### 3. Уборка никогда не мешает работающему индексу

Уборка идёт через **теневой индекс**: `rebuild.ts` строит `index.building.sqlite` с нуля рядом с активным, и всю стройку **активный индекс продолжает обслуживать поиск** — запросы не блокируются никогда. По завершении переключение — это три синхронных `rename` (active → archive, shadow → active), одно атомарное окно.

Отсюда семантика отказов: **есть тень + есть активный = постройка не завершена**; тогда тень — мусор и выбрасывается без церемоний — активный индекс ни секунды не был в опасности.

## Установка

```sh
# Вариант 1: установка прямо с GitHub (рекомендуется) — lib/ закоммичен, локальная сборка не нужна
dsh plugin --profile web add github:drscrewdriver/dsh-search-index#master

# Вариант 2: сборка из локального пути / исходников (см. раздел «Разработка»)

# Перезапустить dsh web — обязательно! Работающий экземпляр не подхватывает слой бандла на лету
dsh web
```

После установки внизу боковой панели появится кнопка **«Поиск»**; Настройки → Плагины обзаводятся карточкой **«Поисковый индекс»**.

> ⚠️ **Доступность GitHub**: установка через github: предполагает, что github.com доступен; в стеснённой сети сначала настройте рабочий прокси или зеркало, иначе `add` застрянет на этапе скачивания.

## Разработка

```sh
pnpm install            # включает цепочку клиентских пакетов @deepseek-ai + tsdown/tsc
pnpm typecheck          # tsc --noEmit
pnpm build              # tsc(lib/types) + tsdown(lib/index.mjs + lib/client.js)
```

### Устройство исходников

```
src/
├── index.ts            # хостовая половина (node): Config-схема + installSettingsSection + маршруты
├── config.ts           # чистая общая конфигурация (enabled/defaultMode + константа пространства имён, без schemastery для клиента)
├── host/               # собственный индекс (сторона хоста)
│   ├── schema.ts       # таблицы: docs / docs_fts(FTS5) / sessions / водяные знаки
│   ├── engine.ts       # запросы
│   ├── extract.ts      # извлекает искомый текст из событий сессии (включая tool/call и tool/result)
│   ├── sync.ts         # SwitchWatermarkSync: скользящая инкрементальная синхронизация по водяному знаку version
│   ├── rebuild.ts      # теневая сборка + атомарное переключение + инспекция восстановления после краша
│   ├── archive-source.ts  # читает архивный набор, удерживая архивированные сессии вне индекса
│   └── snapshot.ts     # экспорт/импорт снапшотов
└── client/
    └── index.ts        # браузерная половина: вход sidebar.footer.action + плавающая панель + строка settings.general.item
```

- **Хостовая половина**: регистрирует ограждённый HTTP-маршрут `/switch-search/api` (`list-sessions` / `content-search` / `search-status`), с ограждением доверия браузера, идентичным шлюзу `/api` DSH (loopback-Host или trustedHosts; cross-site отклоняется).
- **Схема конфигурации**: хост регистрирует пространство имён `switch-search` через сервис `settings` + schemastery-`Config`; клиентская половина зеркально читает и пишет через локальное место store + `settingsScope.bind`; общий чистый модуль `src/config.ts` держит клиентский бандл свободным от schemastery.
- **Сборочная цепочка**: tsdown воспроизводит семантику harness-файла `packages/client/tsdown.client.ts` (баннер `__ModuleLoader__.load`, таблица внешних модулей по платформам, шлюз чистоты бандла).
- **lib/ закоммичен в репозиторий**: установки с GitHub работают на закоммиченном артефакте сборки (dsh при установке из git не запускает `prepare`); `.gitignore` не исключает `lib/`.

## Отношение к официальному поиску боковой панели

- Официальная строка поиска живёт в `sidebar.workspaces` (единственный слот), который внешний плагин **заменить не может**; этот плагин **добавляет отдельный вход** внизу боковой панели через `sidebar.footer.action` — они сосуществуют и не мешают друг другу.
- Официальный поиск по содержимому жёстко зашит в apiproxy и ищет только по `user/message` + `assistant/message`; этот плагин ищет по собственному индексу и открывает `tool/call` + `tool/result`, обеспечивая поиск на уровне инструментов.

## Совместимость и приватность

- Требуется установленный DeepSeek Harness с профилем web; **никакой официальный код не меняется**. Индекс — собственный файл плагина: включён ли официальный `session-query-sqlite`, роли не играет.
- Конфигурация живёт только в пространстве имён settings DSH и в состоянии панели браузера; ничего сверх данных поиска по сессиям не читается и не отправляется.
- Контрактные типы хоста/клиента объявлены структурно в `src/*.ts` (цепочка клиентских пакетов dsh на npm неполна) и сверяются с исходниками harness на этапе сборки.
